| ----------------------------------- | -------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `AliasVault`                        | safety   | `TypeOK`                           | State and reference domains remain well typed.                                                                           |
| `AliasVault`                        | safety   | `StableResourceNamespace`          | References round-trip the connection and alias-ID pair, and equal provider IDs in different connections remain distinct. |
| `AliasVault`                        | safety   | `AuthorizedWrites`                 | Every reconciliation write is scoped to its active connection.                                                           |
| `AliasVault`                        | safety   | `ReconciliationIdempotent`         | Each target reaches a fixed point and cannot be rewritten again.                                                         |
| `AliasVault`                        | safety   | `UnrelatedVaultItemsPreserved`     | Unrelated cipher payload is a frame invariant.                                                                           |
| `AliasVault`                        | safety   | `ProviderDeletePreservesVault`     | Provider deletion does not rewrite vault state.                                                                          |
| `AliasVault`                        | safety   | `ProviderDisablePreservesVault`    | Provider disable does not rewrite or delete vault state.                                                                 |
| `AliasVault`                        | safety   | `CanonicalReferenceSchema`         | Serialized references have exactly the six v2 fields.                                                                    |
| `AliasVault`                        | safety   | `CredentialNonDisclosure`          | Serialized reference information flow excludes credential sources.                                                       |
| `AliasLifecycle`                    | safety   | `TypeOK`                           | Concurrent lifecycle state remains in its declared domains.                                                              |
| `AliasLifecycle`                    | safety   | `StableMutationTarget`             | A dispatched mutation retains its connection/alias target.                                                               |
| `AliasLifecycle`                    | safety   | `AuthorizedMutations`              | Only a connection owning the resource tuple dispatches.                                                                  |
| `AliasLifecycle`                    | safety   | `SuccessRequiresVerifiedRead`      | Toggle bodies cannot establish success.                                                                                  |
| `AliasLifecycle`                    | safety   | `ReplayedResponseIgnored`          | Any replayed response leaves provider state unchanged.                                                                   |
| `AliasLifecycle`                    | safety   | `UnknownOutcomeNotReplayed`        | An unknown mutation outcome is terminal for that request.                                                                |
| `AliasLifecycle`                    | safety   | `DeleteDispatchedAtMostOnce`       | Delete is never automatically replayed.                                                                                  |
| `AliasLifecycle`                    | safety   | `DeleteDoesNotDisable`             | Confirmed and response-lost delete transitions cannot change enabled state.                                              |
| `AliasLifecycle`                    | safety   | `DisableDoesNotDelete`             | Confirmed and response-lost toggles cannot delete the resource.                                                          |
| `AliasLifecycle`                    | safety   | `BoundedInterference`              | Toggle attempts never exceed the production bound.                                                                       |
| `AliasLifecycle`                    | liveness | `Terminates`                       | Under weak client-step fairness, every request reaches a terminal result.                                                |
| `AliasLifecycle` reliable/quiescent | liveness | `AuthorizedSetConverges`           | One authorized client eventually observes its desired state.                                                             |

There are no TLA+ `ASSUME` or `AXIOM` declarations, and the checker rejects their introduction. All
formulas above are evaluated by TLC as invariants or temporal properties. The model constants in
each `.cfg` define the checked abstraction rather than asserting a security result.

## Production refinement gates

| Contract area                       | Canonical vector or trace                                     | Production consumer                                            | Drift detected                                                                                                     |
| ----------------------------------- | ------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| v2 schema and secret exclusion      | `referenceVectors`, `referenceSchema`                         | Core Rust integration test, UniFFI export test, WASM Jest test | Version, field set/order, casing, canonical URL/account scope, unexpected secret fields, parse/serialize behavior. |
| Stable same-origin account identity | second reference vector                                       | Core Rust and WASM reconciliation                              | Loss of connection namespacing or alias-ID-only matching.                                                          |
| Current-reference preservation      | `reconciliationVectors`                                       | Core Rust and existing WASM reconciliation API                 | Address inference, plan/apply drift, repeated writes, unrelated field or cipher mutation.                          |
| Concurrent/replayed toggle          | `lifecycleTraces`                                             | Core Rust HTTP client and WASM fetch surface                   | Trusting a toggle body, wrong request sequence, unbounded attempts, or false convergence.                          |
| Delete/disable separation           | `operationSemantics` plus lifecycle and unknown-outcome tests | Core Rust client and TLA+ transitions                          | Vault-side deletion, conflated state effects, or replay after transport ambiguity.                                 |

`conformance-vectors.json` is the canonical cross-language artifact. The Rust, WASM, and UniFFI
gates read that file directly; copied expectations are not authoritative. The core gate also hashes
the checked `.tla` and `.cfg` files in the declared order and compares that digest with the vector
artifact, so a model edit requires an explicit conformance revision.

## Checked abstraction and unproved boundaries

| Boundary                                             | Status                                                                                                                                                                                                                               | Consequence                                                                                                                                                                                |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| TLA+ state space                                     | Exhaustive for the configured data-independent abstraction: two connections sharing one numeric alias ID, two vault ciphers, two concurrent actors, booleans, deletion, replayed responses, transport ambiguity, and three attempts. | This is finite-state model checking, not an unbounded proof over arbitrary collection sizes. Production tests separately exercise 10,000-item reconciliation.                              |
| TLC fingerprints                                     | State identity uses 64-bit fingerprints. TLC reports its collision-risk estimate for each run.                                                                                                                                       | A fingerprint collision is a small residual checker risk and is reported, not hidden.                                                                                                      |
| Provider/origin validation                           | The model fixes one provider and canonical origin.                                                                                                                                                                                   | URL parsing, UUID validation, and hosted/self-hosted separation are Rust/Serde refinement obligations covered by production tests, not TLA+ string proofs.                               |
| Model-to-code refinement                             | The model digest and shared vectors make the checked model and represented production traces fail together on drift.                                                                                                                 | This is executable translation validation for the represented cases, not a machine-checked total-refinement theorem over every Rust, WASM, or UniFFI execution.                            |
| Rust/Serde/Reqwest/Tokio/WASM/UniFFI implementations | Trusted computing base, exercised by conformance and normal CI.                                                                                                                                                                      | Compiler, runtime, dependency, FFI generator, or memory-safety defects are not proved by TLA+.                                                                                             |
| Provider and network                                 | TLS/authentication correctness and fresh validated `GET` responses are assumptions. Loss, invalid data, concurrent writes, replayed toggle bodies, and ambiguous mutation outcomes are modeled.                                      | A Byzantine provider that lies consistently on fresh reads is outside the claim.                                                                                                           |
| Caller persistence                                   | Not modeled. Reconciliation returns owned decrypted values for the caller's normal encrypt/upload transaction.                                                                                                                       | Crash consistency, encryption at rest, merge policy, and cross-device persistence races remain caller responsibilities.                                                                    |
| Credential coincidence                               | Information-flow origin is modeled; vectors also inject a distinct sentinel.                                                                                                                                                         | The proof means credentials are not sourced into references. It does not forbid a non-secret UUID or address from coincidentally having the same bytes as a credential.                    |
| Availability                                         | Terminal failure is live under fairness; successful convergence has reliable/quiescent assumptions.                                                                                                                                  | Infinite provider failure or interference need not succeed and correctly terminates as an explicit error when the attempt bound is reached.                                                |
